## 许可证

仓库已包含完整的 OSI 认可 MIT License，并填写了版权年份和权利人。除非文件另有说明，本仓库中的 CloudAI 原创内容均按该许可证提供。

## 源码可用性

当前仓库已在 [`Source/CloudAI`](../Source/CloudAI/) 中加入 CloudAI 1.0.1 的完整工作树副本，包括 Python/Tk 桌面应用、Agent 模式、插件宿主与示例、无界面的 Python 与 C++ 实现、测试、Windows/Linux/macOS PyInstaller 配置、所需共享资源以及 HarmonyOS ArkTS/NAPI 工程。私有签名密钥、证书、签名配置文件、口令、生成文件和本地运行数据均未复制进仓库。旧的二进制隐私文档已替换为可审查的多语言 Markdown 政策，打包配置也已加入 MIT License 和第三方声明。

当前环境中，无外部依赖的 Python 测试、桌面 Agent/插件测试、Python 语法检查、C++ CMake 构建、CTest 冒烟测试以及 HarmonyOS 工程级 CMake 入口均已通过。桌面 GUI 与各平台安装包尚未在全部目标系统上完成构建；完整构建 HAP 仍需要兼容的 HarmonyOS SDK、DevEco Studio 和本地签名配置。

仓库没有单独配置的 OpenHarmony HAP 工程。更重要的是，这份工作树副本尚未与任何已有发布产物所使用的提交和精确工具链建立对应关系，因此目前仍不能将已有二进制描述为该源码的可复现构建。

要完成发布源码验证，还需要加入或验证：

- 单独的 OpenHarmony HAP 工程，或修正对外声明的支持范围；
- 锁定的依赖版本和精确的构建工具链版本；
- 从版本标签完整构建 Windows、Linux、macOS Universal 与 HarmonyOS 安装包；
- 在所有声明的平台和架构上完成安装及设备测试；
- 第三方要求的许可证文本和生成的 SBOM；
- 每个发布产物与对应源码提交之间的映射。
