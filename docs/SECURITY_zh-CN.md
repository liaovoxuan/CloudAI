# 安全政策

## 支持版本

| 版本 | 安全支持状态 |
| --- | --- |
| 1.0.1 | 支持 |
| 1.0.0 及更早版本 | 旧版，不提供常规安全修复 |

仅支持最新发布分支。旧版安装包仅用于历史留存，不应在要求当前安全支持的环境中使用。

## 已知凭据存储限制

仓库中的 CloudAI 1.0.1 桌面端、Python 和 C++ 实现会将 API Key 与公开 Provider 设置分开保存，并在状态输出中进行掩码处理，但兼容磁盘格式使用的是可逆混淆，而不是平台密钥库。在各应用改用合适的操作系统凭据存储前，应将本地密钥文件视为敏感文件，并避免使用生产凭据。

## 报告漏洞

不要通过公开 Issue 报告漏洞。请提交[私密漏洞报告](https://github.com/liaovoxuan/CloudAI/security/advisories/new)，并提供：

- 受影响的版本、操作系统、架构和安装包格式；
- 影响范围与受影响组件；
- 可复现步骤或最小化概念验证；
- 脱敏后的日志、截图或崩溃信息；
- 已知的缓解措施；
- 希望使用的署名方式（如有）。

不要提交真实 API Key、访问令牌、私密提示词或个人信息，请使用占位符或测试凭据。

如果 GitHub 私密漏洞报告功能不可用，可以提交一个简短的公开 Issue，请求私密安全联系方式，但不要在该 Issue 中提供漏洞详情。

## 响应与披露

维护者计划在七个自然日内确认收到报告，并在 30 日内提供状态更新。这些是处理目标，不构成服务等级保证。请在公开披露前预留合理的修复时间；条件允许时，项目会与报告者协调披露时间和署名。

## 范围

CloudAI 代码、打包、凭据处理、更新机制及捆绑依赖中的问题属于报告范围。仅存在于第三方 AI 服务或操作系统中的漏洞应报告给对应供应商，但由 CloudAI 集成方式导致的用户风险仍属于本项目处理范围。
